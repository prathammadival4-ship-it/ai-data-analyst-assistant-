Your 45-second introduction

“I built Cloud Analyst, a full-stack AI data analysis app. A user uploads a CSV or Excel file, the backend loads it into a Pandas DataFrame, and then the user can ask questions in plain English. A LangChain dataframe agent uses a Groq-hosted language model and Python tools to compute answers from the data. The React interface presents the results in a chat experience with readable Markdown tables and lists. I focused on making data exploration accessible without requiring users to write SQL or Python.”

End-to-end explanation

  1. Select and upload: The user selects a .csv, .xlsx, or .xls file. React sends it as multipart form data to POST /api/upload.
  2. Validate and parse: Flask checks the filename and supported format, then uses Pandas to read the upload directly from memory without saving a CSV or Excel file to disk.
  3. Return dataset metadata: The API sends a JSON summary with the filename, row and column counts, column names, and a small preview. The UI displays the active dataset.
  4. Ask a question: React sends JSON containing the question to POST /api/query. The server creates a dataframe agent for the active DataFrame.
  5. Compute and explain: The agent uses Python dataframe operations to calculate an answer. The LLM writes a concise response; Markdown is rendered in the chat.

Main API endpoints

GET /

Lightweight health check; returns a JSON status message.

POST /api/upload

Multipart upload; responds with dataset summary or a validation/parsing error.

DELETE /api/upload

Deletes the active in-memory dataset and clears its metadata.

POST /api/query

Accepts {"query":"..."}; responds with the original question and the agent result.

Why use an agent?

A regular chat model may guess at numeric answers. The dataframe agent can call a Python tool that works against the actual DataFrame, then describe the result. The app’s prompt instructs it to avoid invented values and to use concise Markdown, key findings, and comparison tables when appropriate.

Implementation · 03

Technical decisions

What to highlight in the interview

Why React + Vite?

React keeps upload, chat, loading, error, and dataset-summary UI state in focused components. Vite provides a quick local development server and production build.

Why Flask?

The backend is a small JSON API that is straightforward to connect to the frontend. Flask-CORS enables local frontend/backend development across ports.

Why Pandas?

Pandas provides familiar tabular operations and supports both CSV and Excel parsing. The DataFrame is the working representation for analysis.

Why Markdown?

Markdown supports readable headings, emphasized results, bullet lists, and tables. React Markdown plus GFM turns model text into formatted chat content.

Reliability and user experience

  • Checks for missing files, empty filenames, unsupported formats, missing datasets, and blank questions.
  • Uses secure_filename to sanitize uploaded filenames.
  • Shows upload/query loading states and surfaces API/network errors in the interface.
  • Displays a dataset preview and row/column metadata before users ask questions.
  • Uses a bounded model output length and a model available to the configured Groq account.

How to describe your contribution

“I connected a React chat interface to a Flask API, implemented file upload and tabular parsing with Pandas, integrated a LangChain dataframe agent with a hosted LLM, and improved response readability with structured Markdown. I also traced integration errors across the API, model, and UI and validated the complete flow with a sample CSV.”

Demo plan (about 2 minutes)

  1. Introduce the problem: spreadsheet insights should not require writing code.
  2. Upload a small sample CSV and point out its row count, columns, and preview.
  3. Ask a concrete question tied to those columns, such as “Which category has the highest total?”
  4. Show the direct answer, comparison table, and key findings.
  5. Close with current limitations and one production improvement you would make next.
Tip: Bring a small, clean sample CSV with obvious results. Confirm the API key is configured privately and both local servers start before the interview.

Interview Q&A · 04

Practice your answers

Likely questions & honest answers

What problem does the project solve?

It makes basic exploration of tabular files more accessible. Instead of writing a script for every question, a user can upload a file and ask for calculations or patterns in plain language.

How do you make answers data-grounded?

The dataframe agent has a Python tool connected to the active Pandas DataFrame. It can calculate from the dataset rather than relying only on the language model’s memory. I still treat model output as something to verify, especially for consequential decisions.

What happens if the user uploads an invalid file?

The server checks the request and extension, then Pandas attempts to parse the file. The API returns an error response, and the frontend displays the message. A production version should validate file size, content, and schema more thoroughly.

How is the API key handled?

The key is loaded from an environment variable using dotenv and is not included in frontend code. For deployment, I would use a managed secret store, rotate keys, and make sure secrets never enter source control or logs.

What are the current limitations?

The current backend stores the active DataFrame in a process-wide global variable, so it is a single-user/demo design and concurrent users could interfere. Uploads are stored on local disk, there are no user accounts or persistent chat sessions, and arbitrary code execution by the dataframe agent needs stronger isolation before production use.

What would you improve next?

I would add per-user/session dataset storage, size and type limits, authentication and rate limiting, a sandboxed analysis worker, structured logging and tests, deployment configuration, and clearer controls for removing uploaded files. For large datasets, I would avoid loading everything into one in-memory DataFrame.

How did you test it?

I tested the upload and query endpoints with a temporary sample CSV, verified the response status and calculated result, and ran a production build of the frontend. The next step is adding automated unit and integration tests to make those checks repeatable.

A thoughtful closing statement

“This is a working prototype focused on a clear user workflow. I understand the difference between a demo and a production-ready analytics service, especially around isolation, multi-user state, file security, and observability. Those are the first areas I would address as I scale it.”

Question bank · 05

Try these after uploading a dataset

Data questions to ask the AI

Pick a prompt that fits your file. Replace bracketed words with real column names or values from your dataset. Ask one clear question at a time for the best result.

1 · Understand the dataset

  • Summarize this dataset in plain English.
  • How many rows and columns are there?
  • What does each column appear to represent?
  • Show a few representative records.
  • Which columns look numeric, categorical, or date-based?

2 · Check data quality

  • Which columns contain missing values?
  • Are there duplicate rows?
  • Find unusual or potentially invalid values.
  • Are any columns formatted inconsistently?
  • What should I clean before analyzing this data?

3 · Totals and averages

  • What is the total [sales/revenue/amount]?
  • What is the average, median, minimum, and maximum of [column]?
  • How many records are in each [category]?
  • What percentage of the total comes from each category?
  • Calculate the overall [metric] by [group].

4 · Rankings and comparisons

  • Which [product/region/person] has the highest [metric]?
  • Show the top 5 and bottom 5 [categories] by [metric].
  • Compare the average [metric] across [groups].
  • Which category has the largest share of the total?
  • Sort the [categories] from highest to lowest [metric].

5 · Trends over time

  • How does [metric] change over time?
  • Group [sales/events] by month and summarize the total.
  • Which month or date has the highest [metric]?
  • Compare this year with last year, if both are in the data.
  • Are there noticeable seasonal patterns in the dates provided?

6 · Relationships and patterns

  • Which numeric columns appear related?
  • Does [metric] differ across [category]?
  • Are higher [X] values associated with higher [Y] values?
  • Point out notable clusters or outliers in [column].
  • What are three interesting patterns in this dataset?

7 · Focused business questions

  • Which [products] contribute most to [revenue/profit]?
  • Which [region/team] has the lowest [performance measure]?
  • What changed most between [group A] and [group B]?
  • Which records meet [condition]?
  • What practical next steps does this data suggest?

8 · Ask for a clear presentation

  • Give me the answer first, then list the key findings.
  • Show the comparison as a Markdown table.
  • Explain the calculation in simple terms.
  • Include the values you used and state any assumptions.
  • If the dataset cannot answer this, tell me what is missing.
Good question formula: “Calculate [metric] grouped by [category or date], compare the top results, and summarize the main finding.” Avoid treating correlation or patterns as proof that one thing caused another.
